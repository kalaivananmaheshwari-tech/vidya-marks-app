# V4 production configuration inventory — names and presence only

Date: 2026-10-02. Scope: every environment variable consumed by this repository's application/configuration, Docker/Compose, CI and verification scripts; critical inherited PostgreSQL/framework controls are identified separately. **No secret values were printed, requested or configured.** `.env.example` is a template, not evidence that production settings exist.

Presence was inspected without dumping environment/connection files. The existing preview uses an explicitly local synthetic PostgreSQL URL, development mode, `AUTO_MIGRATE=0` and `DEMO_MODE=0`. Its private `.cache` connections are not durable production configuration. The shell has no application/provider deployment variables supplied. Real production/staging host settings were **not inspected or authorized**. A GitHub names-only metadata request was unavailable; actual repository/environment secret/variable configuration is unknown, not assumed absent.

Classification: **Required secret**, **Required non-secret**, **Optional** (including conditional recovery/deployment configuration), **Test-only**, **Development-only**. “Required” in the release policy can be stricter than a code default: flags are explicitly set even when missing defaults safely.

### Variables that do NOT exist in this application

There is **no `SESSION_SECRET`, `AUTH_SECRET`, `JWT_SECRET`, `NEXTAUTH_SECRET`, `OTP_PROVIDER_*`, `SMS_SENDER_ID` or `NEXT_PUBLIC_APP_URL` requirement** in the inspected implementation. Do not invent them. Sessions use32 random bytes, server-side SHA256-hashed tokens and persisted role/membership authority; no JWT/client-signed session. Password hashing uses random salts, not a global password secret. Browser requests are relative `/api`; DNS/public URLs are host configuration and `APP_ORIGINS`, not a new frontend environment contract. Sender/header/template/regulatory setup belongs to the authorized SMS adapter/provider, not guessed application variables.

## Inherited PostgreSQL / operator-client controls

Use an explicit approved DATABASE_URL; do not silently rely on shell defaults selecting another instance. Installed node-pg also honors missing URL components from `PGHOST`, `PGPORT`, `PGUSER`, `PGDATABASE`, **`PGPASSWORD` (secret)**, `PGOPTIONS`, `PGBINARY`, `PGCLIENT_ENCODING`, `PGREPLICATION`, `PGAPPNAME` and `PGSSLMODE`. These are **optional inherited controls**, not a replacement for the required application DATABASE_URL. Their actual production configuration is unknown. `PGCONNECT_TIMEOUT` does not override this app's explicit5s timeout. `USER`/`USERNAME` are OS defaults, not authorized DB identities. Application TLS comes from the URL/driver settings; never use disable/no-verify or `rejectUnauthorized=false` to make a production connection work.

The backup runbook introduces **operator-client settings only**, not app requirements: `BACKUP_SERVICE`/`RESTORE_SERVICE` (non-secret approved service names), `BACKUP_DIRECTORY`/`BACKUP_ARCHIVE` (non-secret restricted paths), `PGSERVICEFILE` (protected connection-profile file), `PGPASSFILE` (secret credential file), and applicable `PGSSLROOTCERT`/`PGSSLCERT`/`PGSSLKEY` (certificate/private-key controls for libpq tools; private keys are secret). Full-DATABASE_URL source files must be treated as secrets. Never print service files, password files, resolved Compose output, Vercel pulled environment files or complete URLs. These operator settings were not configured or executed against any real target.
